# Institutional Edit Ledger Recovery. Approach

Recommended time spent value: 14 hours.

## Submission form text

I treated the task as 2 learned stages over whitespace tokens, after establishing from the training data that every edit starts and ends exactly on whitespace token boundaries and that no 2 distinct edits are ever adjacent, so a binary token tagger plus merge of adjacent positives is an exact span assembler.

Stage 1 is detection. A LightGBM classifier scores every token with 81 features fit per fold from training data only: punctuation shape (mid token colon, star, slash, underscore classes), learned edit rate lexicons for surface forms, prefixes, suffixes and the feminine suffix classes that follow gender marks, neighbor token rates, stem sharing ratios between nearby tokens (this captures paired forms such as a feminine plural, a connector word, then the masculine plural), window position and language. On top of it I ensemble a small bidirectional GRU sequence tagger (hashed character ngram token embeddings plus a language embedding, 5 seeds averaged) which reads the whole token sequence. The GRU is the decisive lever for German, where edits are multi token structures: German token ranking quality rises from 0.19 to 0.28 average precision, German language score from 0.42 to 0.48, and false edits on unchanged rows drop from 80 to 57 of 216. An Italian only rescorer LightGBM with morphological ending rates, article anchor distances and agreement chain features is blended in for Italian. Candidate span generators, gated independently of the token threshold, recover structures the per token path misses: runs of adjacent marked tokens, connector bridged paired forms (the connector tokens are discovered at fit time from interior positions of multi token training edits), and Italian article anchored noun phrases admitted by a cross fit LightGBM gate.

Stage 2 is transduction. Replacements are generated by a hierarchy fit from training pairs at run time: exact and normalized source memories, mark templates induced by character alignment (the stem is abstracted to a variable, so the inserted connector words are learned, never written in code), guarded suffix rewrite rules including Italian slash append rules learned from decomposed multi token edits with agreement across article, noun and adjective, and a measured masculine form fallback for unseen German paired collapses. A group consistency vote across the overlapping windows of each document group (German and English only, where it measured positive) propagates decisions across repeated surface forms.

Per language decision thresholds and blend weights are selected by nested cross validation on a 5 fold grouped split by document, so reported numbers are honest: nested cross validation ELRU 0.5707 (0.5777 with the shipped fixed German threshold), non nested 0.5866, versus 0.25 for predicting no edits and 0.56 for the AI baseline. Per language nested scores: German 0.48, English 0.81, Italian 0.42. The final script refits everything from train.csv, runs in about 2 minutes on CPU, validates the ledger schema before writing, and degrades to a valid empty ledger submission only if a hard failure occurs.

What worked: pattern level learning instead of surface memorization (surface memorization transfers at only 0.30 to 0.37 ELRU because document vocabularies differ), the sequence tagger ensemble for German, threshold independent candidate generators, template induction by character alignment, group level voting, and nested threshold selection. What did not work, all measured and dropped: a span level reranker (true and false spans are lexically identical), document level edit activity priors (every Italian training document is edit active), row level probability gates, deletion prediction (precision 0 at every attempted mechanism, cost of forfeiting about 0.012), a GRU sequence to sequence replacement generator (0.35 versus 0.66 for induced templates), and TFIDF style features (banned, and hashed count features also scored better).

## Compliance notes

- Every lexicon, template, memory and model is fit from train.csv inside solution.py at run time. No encoded content strings appear in source code (verified by grep). No TFIDF or idf weighting anywhere. No external data, no network, no test fitting; the test file is read only to produce predictions row by row (plus the sanctioned within document group consistency vote over test inputs).
- Real ML materially drives predictions: LightGBM detectors, the 5 seed BiGRU sequence tagger, the Italian rescorer and the learned NP gate.
- Runtime about 82 seconds end to end on a 10 core CPU box, far inside the budget. Deterministic across reruns (fixed seeds, fixed thread counts).
- The script accepts python3 solution.py public_dir submission_out, auto detects the data directory if arguments are missing, and writes a strictly validated 445 row submission.
